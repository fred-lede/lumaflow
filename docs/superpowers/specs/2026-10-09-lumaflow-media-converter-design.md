# LumaFlow 媒體轉換器設計規格

日期：2026-10-09  
狀態：設計已確認，待依實作計畫執行

## 1. 產品定位

LumaFlow 是一個跨平台、本機離線、批次處理優先的影音轉換器，支援 macOS、Windows 與 Linux。產品以「無損優先」為核心，而不是宣稱所有格式之間都能位元級無損轉換。

目標使用者包括一般使用者與內容創作者。產品需要讓使用者快速完成常見轉換，同時讓進階使用者看懂編碼器、品質與無損判定。

產品副標暫定為：

> Lossless-First Media Converter

## 2. 設計決策

- 工作台採單頁工作台：檔案、輸出設定與轉換佇列同時可見。
- 視覺採 Apple 玻璃感，跟隨系統明／暗色，也提供手動切換。
- 所有檔案只在本機處理，不需要帳號、雲端上傳或雲端儲存。
- 支援完整批次佇列：多檔案、逐檔狀態、暫停、繼續、取消、重試與排序。
- 品質控制採「簡單預設 + 可展開進階設定」。
- 介面以可讀性優先：一般文字至少 14px，輔助文字至少 12px；狀態不只使用顏色表達。
- 第一版使用 Tauri 2 + React/TypeScript + Rust + FFmpeg/FFprobe。

## 3. MVP 格式範圍

第一版優先支援常用容器與音訊格式：

### 影片

- MP4
- MOV
- MKV
- WebM
- AVI

### 音訊

- MP3
- M4A/AAC
- WAV
- FLAC
- OGG/Opus

格式支援需依實際編碼器與容器組合判斷。當指定組合不相容時，LumaFlow 必須在開始轉換前說明原因與可行替代方案。

ProRes、DNxHD/DNxHR、HEVC、AV1、AIFF、ALAC、字幕封裝，以及 WMV、TS、M2TS、3GP 等格式列為後續擴充，不列入 MVP 驗收範圍。

## 4. 無損優先策略

「無損」在產品中分成三種可理解的處理方式：

1. **無損封裝／直接串流複製**：輸出容器與影音串流相容時，直接重新封裝，不重新編碼影音內容。
2. **無損編碼轉換**：例如 WAV → FLAC，在格式與來源條件允許時使用無損編碼。
3. **重新編碼**：例如 MP4 → MP3，必須重新編碼音訊；介面必須明確標示此結果不屬於位元級無損。

每個佇列項目都必須顯示「無損封裝」、「無損音訊轉換」或「重新編碼」。當轉換會重新編碼時，開始前顯示提醒，但不阻擋使用者繼續。

品質預設：

- 原始／無損優先
- 高品質
- 平衡
- 小檔案

進階設定可調整編碼器、位元率、解析度、幀率、聲道與取樣率。預設不覆蓋來源檔案。

## 5. 單頁工作台

### 主要區域

1. **檔案區**：拖放檔案、選擇檔案、選擇資料夾；空白狀態突出拖放操作。
2. **輸出設定區**：輸出格式、品質預設、無損模式與「顯示進階設定」。
3. **轉換佇列**：固定在頁面下方，顯示每個檔案的格式、處理方式、進度、剩餘時間與操作。

### 主要操作

- 開始轉換
- 暫停全部／繼續全部
- 取消單檔或全部
- 重試失敗項目
- 拖曳調整佇列順序
- 清除完成項目
- 完成後開啟輸出資料夾

### 視覺與可用性

- 使用半透明層、背景模糊、柔和陰影與明確層級呈現玻璃感。
- 玻璃效果不得降低文字對比或造成資訊難以閱讀。
- 支援系統文字放大、鍵盤操作、清楚的焦點狀態與高對比模式。
- 轉換狀態同時使用文字、圖示與顏色表達。

## 6. 佇列狀態與錯誤處理

狀態集合：

- 待處理
- 分析中
- 無損封裝
- 重新編碼
- 轉換中
- 已完成
- 已取消
- 失敗，可重試

每個項目顯示原始檔名、輸出格式、預估大小、進度、剩餘時間、處理方式與詳細資訊入口。

錯誤訊息必須先以一般使用者看得懂的語言說明原因與下一步，再提供可展開的技術詳細資訊。例如不支援的音訊編碼應提示使用者改用重新編碼模式，而不是只顯示 FFmpeg 原始錯誤。

轉換使用暫存檔，成功後才以原子方式寫入輸出檔。取消、失敗或程式中斷後要清理未完成的暫存檔，避免留下看似可用的半成品。

## 7. 技術架構

### UI 層

React + TypeScript 負責工作台、拖放、設定、佇列、進度與無障礙互動。

### 應用核心

Rust 負責檔案分析、轉換計畫、佇列排程、暫停／取消、程序管理、檔案安全與錯誤映射。

### 影音引擎

FFprobe 讀取媒體資訊，FFmpeg 執行封裝、重新編碼與音訊抽取。FFmpeg 採獨立程序執行，避免轉換程序阻塞 UI。

### UI 與核心邊界

UI 不直接執行系統程序，也不直接管理敏感檔案操作。所有檔案選擇、媒體分析、轉換與佇列控制都透過具型別的 Tauri IPC 指令完成。

## 8. 安全與隱私

- 檔案完全在本機處理。
- 不需要帳號、網路連線、上傳或雲端儲存。
- 路徑、檔名與外部程序參數必須驗證與安全轉義。
- 預設不覆蓋來源檔案。
- 僅在使用者明確選擇的輸出資料夾建立檔案。
- 發佈包需附上 FFmpeg 與其他第三方元件的授權資訊。

## 9. 跨平台發佈

第一階段目標：

- macOS：Apple Silicon 與 Intel
- Windows：64-bit
- Linux：AppImage；之後再提供 `.deb`

正式發佈前必須完成 FFmpeg 編碼器組合的 LGPL／GPL 授權審查、第三方授權彙整、macOS 簽署與公證，以及各平台安裝與更新流程驗證。

## 10. 測試與驗收

### 轉換正確性

測試媒體需涵蓋所有 MVP 格式、不同解析度與幀率、多音訊軌、多字幕軌、Unicode 檔名、特殊字元路徑、損壞檔案與不完整檔案。

每次測試必須確認：

- 輸出檔可被 FFprobe 正確讀取。
- 無損封裝時影音串流未被重新編碼。
- 重新編碼時實際編碼器與品質設定符合 UI 顯示。
- 取消或失敗不留下可誤用的半成品。

### 跨平台與 UI

在 macOS、Windows、Linux 驗證拖放、檔案選擇、批次佇列、暫停、繼續、取消、重試、深色／淺色／自動外觀、文字放大、鍵盤操作、輸出權限與清理流程。

### MVP 完成定義

使用者能在三個作業系統上拖入多個檔案，選擇 MP4、MP3、WAV、FLAC 等輸出格式，看懂每個項目是無損封裝或重新編碼，執行完整批次佇列，並在失敗時得到可理解的原因與下一步。

## 11. 明確排除範圍

MVP 不包含影片剪輯、特效、濾鏡、線上下載器、雲端轉換、DRM 破解或取代專業影音播放器的功能。
